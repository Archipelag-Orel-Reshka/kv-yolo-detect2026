# kv-yolo-detect2026

Конвейер, USB-камера и подсчёт деталей для прикладной робототехники
на региональном этапе «Новая высота 2026», Владимир.

[Конкурсное ТЗ](docs/README.md) описывает требования и оценивание.
[Работа с прошивкой](firmware/README.md) описывает сборку, загрузку и USB-команды.
[Проверка оборудования](docs/hardware-check.md) фиксирует результат проверки на площадке.
[Подготовка датасета](docs/dataset.md) описывает 50 изображений для загрузки в Roboflow.
[Обучение YOLO11n](docs/training.md) описывает разметку, CPU-обучение и проверку детектора.
[Дообучение v2](docs/fine-tuning-v2.md) описывает новую модель,
разделение 80 изображений и сравнение при рабочем пороге панели.
[Проверка всех 100 баллов](docs/competition-checklist.md) содержит каждый критерий,
сценарий зачётного прогона и перечень файлов для сдачи.
[Программная проверка](docs/software-verification.md) разделяет выполненные
тесты и оставшиеся проверки на площадке.

## Структура

```text
firmware/conveyor_controller/  прошивка DXL-IoT, мотор ID 22
firmware/libraries/            библиотека производителя, закреплённая версия
tools/                        сборка, загрузка и управление с ноутбука
docs/                         ТЗ и протокол обмена
backend/                      сервер панели: камера, YOLO, счётчики, лента
frontend/                     веб-панель: видео, Запуск/Стоп, счётчики
dataset/                      исходные фотографии команды
dataset/roboflow-upload/       50 изображений, train/valid/test
models/                       веса YOLO11n и обученной модели
reports/                      автоматически сохранённые отчёты
tests/                        проверки протокола и защит прошивки
```

Управление лентой проверено на оборудовании. YOLO11n обучена на CPU
80 эпох и дообучена ещё 80 эпох на версии датасета v2 для классов
`Pin`, `Piston`, `Shatun`. Активные веса v2 находятся
в `models/conveyor-yolo11n.pt`. При пороге 0.25 проверены 12 тестовых
кадров с 24 объектами без пропусков и лишних детекций.
Добавлены веб-панель с видео и разметкой YOLO, кнопки Запуск/Стоп,
счётчики по классам и общий итог. Названия на видео и в панели:
Клапан, Поршень, Шатун. Отчёты TXT/CSV/JSON формируются автоматически
для команды «Технопарк-33» после каждого подсчёта, при Stop и завершении.
Точность на физической ленте проверять после окончательного крепления камеры.

## Панель

При первой установке на другом компьютере подготовить Python 3.12
и CPU-сборку PyTorch:

```bash
uv venv --python 3.12
uv pip install --python .venv/bin/python \
  torch==2.14.1+cpu torchvision==0.29.1+cpu \
  --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv/bin/python -r requirements.txt
```

На ноутбуке команды зависимости уже установлены. Запуск из корня проекта:

```bash
./tools/run-panel.sh
```

Открывается `http://127.0.0.1:8000/`. Скрипт использует постоянные USB-имена
Logitech C510 и контроллера, горизонтальную линию `--axis y`
и команду «Технопарк-33». Для другой камеры/платы можно передать
`--source 3 --port /dev/ttyUSB0`. Прямой запуск:
`.venv/bin/python backend/main.py --source 3 --axis y --team 'Технопарк-33'`.
При прямом запуске порт контроллера ищется по чипу
CH340/Arduino, иначе `--port /dev/ttyUSB0`. Веса берутся из
`models/conveyor-yolo11n.pt`, затем `models/best.pt`, без них
`yolo11n.pt` (COCO, для проверки панели). Порог по умолчанию 0.25,
разрешение YOLO 512 px, обработка на CPU.
Список камер: `--list-cameras`. Без ленты и камеры, по видеофайлу:
`--source video.mp4 --no-conveyor`.

Деталь считается один раз, когда центр её трека пересекает линию
подсчёта (жёлтая на видео). Линия задаётся `--line 0.5 --axis x`,
полоса нечувствительности `--margin 0.05`. Номер трека сохраняется,
пока деталь стоит на остановленной ленте, поэтому Stop/Start не даёт
повторного учёта. Счётчики сохраняются в `reports/conveyor/current.json`
и восстанавливаются при перезапуске. ID треков не восстанавливаются:
во время зачётного прогона процесс не перезапускать.
«Сброс счётчиков» на пустой остановленной ленте начинает новый прогон,
предыдущие файлы остаются. Учитываемые классы: `--classes a,b,c`.

Отчёты каждого прогона находятся в `reports/conveyor/run-<id>.txt`, `.csv`
и `.json`. Содержат название команды, дату, количества и общий итог.
Ссылки TXT/CSV в панели позволяют скачать уже автоматически созданный файл.
При ошибке записи показано сообщение, новый запуск запрещён до восстановления
сохранения. Папка задаётся `--reports-dir`, команда через `--team`.

Лента запускается только кнопкой: `INIT`, затем `START`, затем `PING`
каждые 200 мс. После перезапуска платы, обрыва связи или аварии
контроллера панель показывает ошибку и сама ленту не запускает.

## Оборудование

На фото контроллер соответствует DXL-IoT с Ethernet/microSD расширением.
Основная плата программируется как Arduino Mega 2560, ATmega2560, 16 МГц.
Мотор подключён к встроенной шине Dynamixel, адрес 22.
На площадке диагностикой подтверждён MX-64, номер модели 310,
протокол 1.0, скорость шины 1000000 бод, ID 22.
USB на ноутбуке: CH340, `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`.
Внешняя камера: Logitech C510.

Ethernet-расширение для связи по USB не требуется. Прошивка его не использует.
USB питает логику платы; питание мотора должно соответствовать его модели.
