# Программная проверка, 14 октября 2026

Команда «Технопарк-33». Регламент проверен по исходному PDF, таблица
в [чеклисте](competition-checklist.md) содержит 25 отдельных проверок
с суммой 100 баллов. Это перечень критериев, не оценка судьи.

## Выполненные проверки

- 39 Python-тестов протокола, счётчика, HTTP, датасета и отчётов.
- 5 JavaScript-тестов интерфейса: поля API и русские названия,
  недопустимая скорость не отправляет START, повторный запуск блокируется
  сразу, Stop остаётся доступен, ошибки команд и отчёта отображаются,
  потеря связи запрещает запуск. Тесты используют контролируемые ответы API.
- Нативные C++-проверки управления и состояний прошивки.
- Настоящая YOLO11n и ByteTrack на CPU на трёх контрольных снимках
  с программным перемещением через линию, паузой и продолжением.
  Поршень, Шатун и Клапан добавили по одному, итог 3. Это искусственный
  сценарий на снимках, а не запись физического прогона. Кириллица на
  размеченных кадрах проверена визуально.
- Полный HTTP-цикл с настоящим счётчиком и отчётами, имитатором прошивки
  и заданными детекциями: Start, пересечение, Stop, 600 кадров паузы,
  Start, остальные детали, Stop. TXT/CSV/JSON совпадают с API, команда
  и дата присутствуют, прежний отчёт остаётся после нового прогона.
- Logitech C510 по постоянному USB-имени: живой JPEG 640×480,
  около 23 кадров/с с детектором на CPU, ошибок камеры и модели нет.
- Живой контроллер: ID 22, MX-64, модель 310, Dynamixel 1.0,
  1000000 бод, поддерживается. После запуска обновлённого сервера
  `running=false`, `speed=0`, автоматического запуска нет.
- Из прежней сессии сохранены фактические счётчики 1/1/1, общий итог 3,
  снятые через API перед обновлением. Они восстановлены в новой панели.
  TXT и JSON живой панели содержат те же значения. Счётчики для зачётного
  прогона сбрасывает команда на пустой остановленной ленте.

## Что ещё подтвердить на площадке

Точность каждого вида и отсутствие повторов после Stop/Start проверить
на независимом физическом прогоне после окончательного крепления камеры.
Провести цикл питания с мотором и контроллером. Повторить запуск и
остановку с новой панелью, сверить экран с отчётом и ручным подсчётом
проверяющего. Проверка движения прежней прошивки описана отдельно в
[протоколе оборудования](hardware-check.md).

Чертёж, лазерная резка, крепление камеры, проект слайсера, исходная модель,
файл печати, фотографии и измеренные размеры пока не предоставлены.
Эти критерии отмечены в чеклисте и не считаются выполненными автоматически.

Запуск проверок: `./tools/check.sh`. Для JavaScript-тестов нужен Node.js;
сама панель работает через Python и браузер, без сборки фронтенда.
