# YOLO11n для конвейера

Исходный архив команды: `models/kv-yolo.v1-v0.1.0.yolov11.zip`.
Классы сохраняются по разметке Roboflow:

| ID | Название | Деталь |
| --- | --- | --- |
| 0 | Pin | Клапан |
| 1 | Piston | Поршень |
| 2 | Shatun | Шатун |

Модель детектора: `models/conveyor-yolo11n.pt`.
Программа обучения: `tools/train_yolo.py`.
Параметры: `config/yolo11n-training.yaml`.
Веб-панель автоматически выбирает эти веса, CPU, 512 px и `conf=0.25`.

## Результат запуска

14 октября 2026 года завершены все 80 эпох на AMD Ryzen 7 7735HS,
CPU-сборка PyTorch. Время обучения около 5 минут 46 секунд.
Лучшие веса включены в репозиторий, размер около 5.3 MiB.

| Выборка | Precision | Recall | mAP50 | mAP50-95 |
| --- | ---: | ---: | ---: | ---: |
| valid, 3 кадра | 95.4% | 100% | 99.5% | 96.2% |
| test, 3 кадра | 87.0% | 100% | 99.5% | 82.9% |

На тестовых изображениях при `conf=0.25` найдено ровно по одной детали:
Piston с уверенностью 0.987, Shatun 0.958, Pin 0.368. Все три класса
определены правильно, рамки просмотрены. Pin пока имеет более низкую
уверенность; порог 0.5 отсеет этот тестовый пример. Для следующей версии
сними дополнительные ракурсы, повороты и положения маленьких деталей.
Отдельный запуск проверочного скрипта дал около 20 мс на inference одного
кадра 512 px на CPU; это не замер всего видеоконвейера.

SHA-256 готовых весов:
`333a8d1648370557e762392b9753f830da32f7a0f886196b8533f02a8e4e5fb4`.

После объединения с веб-панелью проверен её реальный ByteTrack:
каждый из трёх тестовых объектов получил track ID и правильный класс.
Пройдены все 30 тестов проекта. Панель выбирает обученный checkpoint
раньше резервных COCO-весов. Версия Ultralytics в основных зависимостях
согласована с версией обучения, чтобы установка не требовала двух
несовместимых версий одновременно.

## Подготовка датасета

Архив сохранён без изменений и распакован в `models/annotated-source/`.
В нём 50 изображений и 131 размеченный объект. У 130 объектов разметка
полигоном, у одного рамкой. Для YOLO11n detection полигоны преобразованы
в охватывающие рамки. Исходная полигональная разметка сохранена.

В выгрузке Roboflow были относительные пути `../train/images` и т.д.
Они заменены локальной конфигурацией подготовленного набора. Шесть групп
исходников были перемешаны между выборками. Восстановлено распределение
из манифеста фотографий, чтобы варианты кадра не попадали в разные выборки:

| Выборка | Изображений | Pin | Piston | Shatun |
| --- | ---: | ---: | ---: | ---: |
| train | 44 | 60 | 33 | 32 |
| valid | 3 | 1 | 1 | 1 |
| test | 3 | 1 | 1 | 1 |

Аудит: `reports/dataset-audit.json`. Проверены нормализованные координаты,
ID классов, целостность изображений, наличие всех классов и отсутствие
точных дублей и пересечения исходников между выборками.

```bash
.venv/bin/python tools/prepare_training_dataset.py
```

Скрипт не перезаписывает готовые папки. Для новой версии архива сначала
сохрани текущий набор или укажи отдельный `--output`; каталог исходной
распаковки также должен быть свободен. Связь файлов с группами берётся из
`dataset/roboflow-manifest.csv`, а при его отсутствии из сохранённого
`config/dataset-source-groups.json`. Для другой версии снимков эту связь
нужно обновить.

## Установка на Linux с AMD

Обучение и проверка выполняются на CPU. CUDA не требуется.
Установи CPU-сборку PyTorch перед остальными пакетами:

```bash
uv venv --python 3.12
uv pip install --python .venv/bin/python \
  torch==2.14.1+cpu torchvision==0.29.1+cpu \
  --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv/bin/python -r requirements-training.txt
```

В `models/base/yolo11n.pt` нужны исходные COCO-веса YOLO11n.
Для текущего обучения использован уже имеющийся локальный официальный
checkpoint, проверены режим detection и 80 исходных COCO-классов.
При новом запуске его можно скачать из
[официальных моделей Ultralytics](https://docs.ultralytics.com/models/yolo11/).

## Обучение и проверка

```bash
.venv/bin/python tools/train_yolo.py
.venv/bin/python tools/check_model.py --source models/training-dataset/test/images
```

Обучение выполняет ровно 80 эпох: early stopping отключён через `patience: 0`.
Используются 512 px, batch 8, AdamW, шесть CPU-потоков, предварительно
обученные веса. Mosaic отключён, поскольку детали на реальной ленте
поступают по одной и маленькие пальцы не нужно дополнительно уменьшать.
Есть небольшие изменения освещения, положения и поворота.
Настройки сохранены в YAML. Набор маленький, поэтому изображения кэшируются
в RAM. Seed фиксирован; RAM cache и различия библиотек/оборудования могут
давать отличия между повторными запусками.

Лучший checkpoint выбирается по validation и копируется в
`models/conveyor-yolo11n.pt`. Для проверки используются отдельные
validation и test. Три тестовых кадра не использовались для обновления весов.
Итоговые метрики, прогнозы и SHA-256 весов сохраняются в
`reports/yolo11n-evaluation.json`, история 80 эпох в
`reports/yolo11n-training.csv`.
Изображения с рамками находятся в `models/evaluation/test-predictions/`.

Полный журнал запуска: `build/training.log`.
Прогресс по эпохам: `build/training-progress.json`.
Повторный запуск в ту же папку запрещён, для новой сессии используй `--name`.

Это первый небольшой датасет, основанный на 13 исходных кадрах.
В valid и test по одному объекту каждого класса. Даже высокий mAP на них
не заменяет проверку на новых кадрах движущейся ленты, с другими положениями
деталей и на пустой ленте. В этой сессии подключена только встроенная камера
ноутбука; внешняя USB-камера Logitech отсутствует. Проверка её видеопотока
не выполнялась.
