# Конкурсное задание

Источник: [регламент прикладной робототехники «Новая высота 2026»](https://ai.kvantorium33.ru/static/docs/reglamentAR.pdf), проверен 14 октября 2026 года.
Это изложение требований для разработки, а не замена регламента.

Участвуют шесть команд по три человека. У каждой команды своя конвейерная
лента. На выполнение отведены два соревновательных дня.

## Что нужно сделать

1. Настроить оборудование, проверить связь и работоспособность.
2. Написать прошивку Arduino и программу на компьютере.
3. Сделать графический или веб-интерфейс с запуском и остановкой ленты.
   При подаче питания лента сама не запускается.
4. Сделать чертёж крепления камеры, вырезать детали на лазере и собрать.
   Камера должна быть прочно закреплена над зоной подсчёта.
5. Показать видео с камеры, счётчики трёх видов деталей и общий итог.
6. Распознавать и считать детали без повторного учёта при остановке и
   продолжении движения.
7. Автоматически сохранять отчёт с названием команды, датой, количеством
   по каждому виду и общим итогом. Отчёт должен совпадать с экраном.
8. Показать полный цикл работы без ручного исправления счётчиков.
   Сдать исходники и объяснить запуск.
9. Напечатать выданную модель из PLA, сохранить проект слайсера и файл
   печати, сделать фотографии процесса и результата. Форму и размеры
   модели менять нельзя. Удалить мешающие поддержки, проверить размеры.

Судья подаёт детали каждого вида по одной, без наложений, в случайном
порядке. Во время проверки ленту один раз остановят и снова запустят.
Количество в отчёте сравнивают с подсчётом судьи.

## Решения команды

Работаем на ноутбуке под Linux. Контроллер DXL-IoT подключён по USB,
мотор Dynamixel имеет ID 22, камера USB. YOLO11n обучена на CPU для
классов Pin, Piston, Shatun. Панель, детектор и отчёт показывают названия
Шпилька, Поршень, Шатун. Команда «Технопарк-33». В регламенте нет требования
использовать именно YOLO. Крепление камеры делает другой участник команды.

[Проверка каждого балла](competition-checklist.md) содержит все отдельные
критерии и сценарий демонстрации. Программные проверки не заменяют
физический прогон, измерение напечатанной детали и сдачу файлов.

План программной части: сначала прошивка и связь, затем камера и веб-панель,
обучение детектора, подсчёт при пересечении зоны и проверка остановки,
автоматический отчёт. Состояние подсчёта нельзя сбрасывать при Stop/Start.
