# Управление конвейером по USB

Прошивка предназначена для DXL-IoT на ATmega2560 с родным трансивером
Dynamixel. Верхнее Ethernet/microSD расширение не участвует в обмене.
Мотор имеет ID 22. USB-команды: 115200 бод, ASCII, конец строки LF.

При старте прошивка ищет ID 22 на скоростях 1000000, 57600, 115200,
9600, 19200, 38400, 250000, 500000 и 2000000, с протоколами 1.0 и 2.0.
Поиск читает номер модели. Для известных моделей отключает момент
и задаёт нулевую скорость. Самостоятельного запуска нет.

В первой версии разрешены проверенные таблицы регистров:

| Модель | Номер модели | Протокол |
| --- | ---: | --- |
| AX-12 / AX-12A | 12 | 1.0 |
| XL-320 | 350 | 2.0 |
| XL430-W250 | 1060 | 2.0 |

Другая модель появится в диагностике с `supported=false`. Прошивка
откажет в запуске до добавления её таблицы регистров по документации.
Одинаковый ID не означает одинаковую модель или протокол.

## Подготовка

Нужны Arduino CLI и core `arduino:avr`. Библиотека производителя уже
в `firmware/libraries`, отдельно скачивать её не требуется.

```bash
arduino-cli core install arduino:avr
uv venv --python 3.12
uv pip install --python .venv/bin/python -r requirements.txt
```

Если порт выдаёт `Permission denied`, для текущего подключения:

```bash
sudo setfacl -m u:mavxa:rw /dev/ttyUSB0
```

Постоянный вариант на CachyOS: `sudo usermod -aG uucp mavxa`, затем
полностью выйти из сеанса и войти снова. После переподключения USB
временное ACL может исчезнуть.

## Сборка и загрузка

Из корня проекта:

```bash
./tools/build-firmware.sh
./tools/upload-firmware.sh
```

Сборка сохраняет обычный `.ino.hex` в `build/firmware`.
Загрузка использует его и проверяет запись. Ethernet-модуль и ESP32
не прошиваются. Порт должен вести к основному ATmega2560.
Закрой монитор порта перед загрузкой. Лента должна быть остановлена,
поскольку открытие порта может перезагрузить текущую прошивку.

Перед первой заменой сохрани flash и EEPROM штатным `avrdude` с
программатором `wiring`, MCU `m2560`, скоростью загрузчика 115200.
Резервные копии клади в `backups/`, они не попадают в Git.
Никогда не загружай `.with_bootloader.hex` через обычную USB-загрузку.

## Проверка без движения

```bash
.venv/bin/python tools/conveyor.py status
.venv/bin/python tools/conveyor.py scan
.venv/bin/python tools/conveyor.py init
```

`status` показывает номер модели, протокол, скорость шины и состояние.
`init` переводит поддерживаемый мотор в режим непрерывного вращения,
но оставляет момент выключенным и скорость нулевой. Для AX-12 меняются
угловые ограничения в EEPROM, для XL-320/XL430 меняется регистр режима.
Повторная инициализация не перезаписывает уже правильный режим.
ID и baudrate мотора прошивка не меняет.

После проверки направления можно выполнить короткий физический тест:

```bash
.venv/bin/python tools/conveyor.py run --speed 50 --seconds 3
```

Отрицательная скорость задаёт противоположное направление. Диапазон
ограничен от -300 до 300, нулевая скорость передаётся через `STOP`.
Это значения регистров, не см/с: AX-12 в wheel mode управляет мощностью,
XL430 задаёт скорость вращения. Первый тест лучше начать с 50.
Скрипт отправляет heartbeat и автоматически останавливает мотор по
истечении времени или Ctrl+C. Без heartbeat контроллер отключает
движение примерно через одну секунду, затем для запуска нужен `INIT`.
При физическом обрыве DXL-кабеля команда остановки не дойдёт до мотора;
прошивка повторяет остановку, но аппаратное отключение питания остаётся
нужным для такой неисправности.

## USB-протокол для будущего сервера

| Команда | Действие |
| --- | --- |
| `STATUS` | Строка `STATUS {JSON}` со всеми состояниями |
| `SCAN` | Поиск ID 22, запрещён при неподтверждённой остановке |
| `INIT` | Остановка и настройка режима, без включения момента |
| `START 50` | Проверка готовности, скорость, затем включение момента |
| `PING` | Heartbeat, отправлять каждые 200–250 мс |
| `STOP` | Отключение момента и нулевая скорость |

Ответы `OK <команда>` и `ERR <причина>` завершаются LF.
`READY KV_CONVEYOR_V1` сообщает о перезапуске платы.
`running` означает подтверждённую команду включения, не измерение
движения самой ленты. `stop_pending=true` означает, что подтверждение
остановки не получено. Backend должен показывать это как ошибку.
После разрыва связи или перезапуска не отправлять `START` автоматически.
